---
title: "Run a public demo"
description: "A throwaway demo instance with a nightly full reset, in its own stack."
---

The public demo of Looty is a separate stack, never a real instance: sign-in is replaced by « Enter the demo », and every visitor gets a throwaway copy of the *Looty Demo* workspace with fictional data. Nothing is kept.

```sh
mkdir -p /srv/looty-demo && cd /srv/looty-demo
curl -LO https://raw.githubusercontent.com/untypequicode/looty/main/docker-compose.demo.yml
curl -o .env https://raw.githubusercontent.com/untypequicode/looty/main/.env.demo.example
# DB_PASSWORD: openssl rand -hex 16
docker compose -f docker-compose.demo.yml up -d
```

The stack has its own database and volumes (`demo_postgres`, `demo_uploads`), its own Traefik router names (`looty-demo`) and memory limits on every container. Point the DNS record of `DEMO_DOMAIN` to the machine and let your Traefik reach the stack (see [Install](/docs/host/install/)).

## Cleaning and nightly reset

- A visitor's copy is deleted 24 hours after it was created, whatever happens.
- **Every night**, at `LOOTY_DEMO_RESET_HOUR` (default 3, in `CALENDAR_DEFAULT_TZ`, UTC otherwise), the backend deletes **every** copy, expired or not: accounts, workspaces and files. People still in the demo start a new copy at their next visit. `LOOTY_DEMO_RESET_HOUR=off` turns the reset off. The template is generated by code, so there is nothing to restore.
- `LOOTY_DEMO_MAX_COPIES`, `LOOTY_DEMO_COPIES_PER_IP_HOUR`, `LOOTY_DEMO_MAX_FILE_MB` and `LOOTY_DEMO_MAX_COPY_MB` bound the load (see the [environment reference](/docs/reference/environment/)).

## Staying up to date and watched

Run an update every night, after the reset, for example with a cron entry in the stack folder:

```sh
30 3 * * * cd /srv/looty-demo && docker compose -f docker-compose.demo.yml pull -q && docker compose -f docker-compose.demo.yml up -d
```

Watch `https://<DEMO_DOMAIN>/api/health` from an uptime monitor, and the free disk space of the volume that holds `/var/lib/docker`.
