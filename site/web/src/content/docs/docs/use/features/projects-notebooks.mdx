## Notebooks

- **Execution engine**: code runs either in your browser (Pyodide, the default) or on the project's **Jupyter server**. The choice is saved in the notebook and applies to everyone; each person has their own kernel, outputs are shared.
- **Project dependencies**: libraries are listed in `requirements.txt` at the root of the project and installed by each Pyodide kernel when it starts. A library only enters the list through an explicit action (*Install* button, `%pip install`, or editing the file).
- **Project modules**: a Python file of the project that cells can import by name.
- **Jupyter server**: a person who can edit the project declares an external server (address, token, default kernel). Only the Looty server contacts it and the token is never shown. The instance administrator must allow private networks if needed (`JUPYTER_ALLOW_PRIVATE`, see [Jupyter for hosts](/docs/host/services/)).
- **Public link**: visitors see the notebook as saved, without running it.
- **Text toolbar**: while a text cell is being edited, buttons insert bold, italic, a link, an image, a formula or a bulleted list around the selection.
- **Export**: the *Export* menu saves the notebook as a web page (`.html`), a PDF (through the browser's print dialog), a Python script (`.py`, one `# %%` block per cell) or a standalone `.ipynb` in which the project's images are attached to their cells. Outputs are those shown on screen.
- **Code completion**: in a code cell, suggestions appear while typing (or with Ctrl+Space). With Pyodide they come from Jedi, once Python has started; with a Jupyter server, from the kernel itself, through the Looty server.

## R, R Markdown and Quarto

- **R notebooks, in the browser, with nothing to set up**: in the *Engine* dialog, pick **R (browser)**. R runs in your browser with [WebR](https://docs.r-wasm.org/webr/latest/) (R compiled to WebAssembly), like Python runs with Pyodide: no server, no Jupyter, no install. The choice is saved in the notebook (`kernelspec` `ir`, language R), so the notebook also opens in JupyterLab. Each person has their own R session and the outputs are shared, as for Python. Cells get R syntax highlighting and completion (base R and loaded packages); text, messages, warnings, errors, data frames (HTML tables) and plots (PNG) are shown. The engine is served by Looty itself (no third-party CDN, works on self-hosted and offline instances) and is downloaded only when a notebook first runs R: about 30 MB the first time, then kept by the browser. Package installation is the exception: `install.packages("x")` or `webr::install("x")` in a cell downloads WebAssembly builds from the public WebR repository (`repo.r-wasm.org`), only when your code asks for it. To install packages at every start, list them (one per line, `#` for comments) in a project file named `r-packages.txt`; adding to it is manual, unlike `requirements.txt` for Python.
  - **Limits of WebR**: a running calculation cannot be interrupted, only stopped by *Restart R* (the R session is lost); no SVG plots yet (PNG only); only packages built for WebAssembly exist (most pure-R packages and many popular compiled ones); files written by R stay in the browser session, read project files (`read.csv("data.csv")`) directly; memory is limited by the browser.
- **R notebooks on a Jupyter server**: instead, pick the project's Jupyter server and an R kernel (IRkernel, usually `ir`) in the *Engine* dialog: all packages of that machine, real interruption, SVG plots, completion from the kernel. The Python engine (Pyodide) does not run R: an R cell run with it shows an explicit message, nothing is run as Python.
- **R Markdown and Quarto documents**: in the file tree (or the project menu while the file is open), *Open as notebook* converts a `.Rmd` or `.qmd` file into a new `.ipynb` next to it, set to the *R (browser)* engine (change it in the *Engine* dialog). The YAML header becomes a raw cell, text becomes Markdown cells, ```` ```{r} ```` chunks become code cells and keep their exact header (`echo=FALSE`, `fig.width=6`, Quarto `#|` lines). Chunks of another engine (bash, sql…) become raw cells that are never run. The conversion is lossless: *Export* offers `.Rmd` and `.qmd` and the document comes back as it was (outputs are not written to these files).
- **Rendering**: the HTML and PDF exports honour `echo=FALSE`, `include=FALSE`, `results="hide"` and the Quarto `#| echo: false` lines, and leave out the YAML header.
- **R panels**: on an R notebook run in the browser (WebR) or by a Jupyter server, the panel button of the toolbar opens four tabs. *Environment* lists the session's variables (name, type, size; click a data frame to preview its first rows) and refreshes after each calculation. *Plots* keeps the plots of the cells and of the console in order, with PNG and SVG export (SVG when the kernel sends one). *Help* shows the documentation of a function (`mean`, `stats::lm`, or `?mean` in the console). *Console* runs R on the same kernel as the cells. These requests are silent: they never create a cell or an execution number. Ctrl+Shift+Enter runs the chunk, Ctrl+Alt+Enter sends the current line or selection to the console. Running a request needs the right to edit and a connected kernel; a long calculation delays the answer.
